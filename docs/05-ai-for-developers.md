# 다섯 번째 학습: 개발자의 AI 활용법

> 목표: 개발자가 AI를 코드 작성 도구가 아니라, 이해, 설계, 디버깅, 리뷰, 학습을 돕는 파트너로 활용하는 방법을 익힌다.

## 오늘의 결론

```text
개발자는 AI에게 코드를 무작정 대신 쓰게 하기보다,
코드 이해, 에러 분석, 리팩터링 방향, 테스트 케이스, 문서화에 활용하는 것이 좋다.
AI가 만든 코드는 반드시 직접 읽고 검증해야 한다.
```

## 한눈에 보기

| 활용 분야 | 사용 방법 |
| --- | --- |
| 코드 이해 | 낯선 코드의 흐름과 역할 설명 받기 |
| 디버깅 | 에러 원인 후보와 확인 방법 정리하기 |
| 리팩터링 | 개선 방향과 위험한 변경 구분하기 |
| 테스트 | 빠진 테스트 케이스 아이디어 얻기 |
| 문서화 | README, 주석, API 설명 초안 만들기 |
| 학습 | 모르는 개념을 쉬운 예시로 설명 받기 |

## 1. 오늘 이걸 공부한 이유

개발자는 AI를 쓰면 코드를 더 빨리 만들 수 있다. 하지만 더 중요한 것은 코드를 더 빨리 이해하고, 문제를 더 체계적으로 확인하고, 놓친 부분을 더 잘 찾는 것이다.

```text
AI에게 모든 코드를 맡긴다 -> 위험하다.
AI에게 코드 이해와 검토를 돕게 한다 -> 좋다.
AI가 만든 결과를 직접 읽고 실행해서 확인한다 -> 꼭 필요하다.
```

## 2. 코드 이해에 활용하기

처음 보는 코드는 바로 수정하기보다 먼저 흐름을 이해해야 한다.

```text
너는 초보 개발자를 도와주는 선배 개발자야.
아래 코드를 읽고 무엇을 하는 코드인지 설명해줘.
함수별 역할, 전체 흐름, 중요한 변수, 주의할 점을 나눠서 알려줘.

코드:
[여기에 코드 붙여넣기]
```

## 3. 디버깅에 활용하기

에러가 발생했을 때 AI에게 바로 정답을 요구하기보다 원인 후보와 확인 방법을 요청한다.

```text
아래 에러가 왜 발생했는지 설명해줘.
가능한 원인을 우선순위대로 정리하고,
각 원인마다 확인 방법과 해결 방법을 알려줘.
추측이 필요한 부분은 추측이라고 표시해줘.

에러:
[에러 메시지]
```

## 4. 리팩터링에 활용하기

리팩터링은 코드만 바꾸는 일이 아니라 위험을 줄이는 일이다. 그래서 AI에게 바로 수정 코드를 만들게 하기 전에 문제점과 위험한 변경을 먼저 물어보는 것이 좋다.

```text
아래 코드를 리팩터링하고 싶어.
바로 코드를 바꾸기 전에 문제점, 개선 방향, 변경 시 위험한 부분을 먼저 설명해줘.

코드:
[코드]
```

## 5. 테스트에 활용하기

AI는 빠진 테스트 케이스를 떠올리는 데 도움이 된다.

```text
아래 기능에 필요한 테스트 케이스를 제안해줘.
정상 케이스, 예외 케이스, 경계값 케이스로 나눠줘.

기능:
[기능 설명]
```

## 6. 개발자가 조심해야 할 점

```text
AI가 만든 코드를 그대로 붙여넣지 않는다.
실행 결과와 테스트로 확인한다.
보안, 개인정보, 인증 정보는 입력하지 않는다.
라이브러리 버전이나 최신 API는 공식 문서로 확인한다.
내가 이해하지 못한 코드는 내 코드가 아니다.
```

## 7. 설명할 수 있는 문장

개발자의 AI 활용법에 대해서는 이렇게 설명할 수 있다.

> 개발자가 AI를 잘 활용한다는 것은 코드를 대신 맡기는 것이 아니라, 이해와 판단을 더 빠르게 하기 위해 AI를 사용하는 것입니다. 특히 코드 설명, 에러 분석, 리팩터링 방향, 테스트 아이디어, 문서화 초안에 활용하면 좋고, AI가 만든 코드는 반드시 직접 검토해야 합니다.
