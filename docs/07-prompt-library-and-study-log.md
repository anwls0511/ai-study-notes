# 일곱 번째 학습: 프롬프트 라이브러리와 학습 기록 관리

> 목표: 좋은 프롬프트를 한 번 쓰고 버리지 않고, 다시 사용할 수 있는 자산으로 정리하는 방법을 익힌다.

## 오늘의 결론

```text
AI 활용 능력은 프롬프트를 매번 새로 만드는 능력만이 아니다.
잘 된 프롬프트와 실패한 프롬프트를 기록하고, 목적과 사용 상황별로 정리해야 실력이 쌓인다.
프롬프트 라이브러리는 나만의 AI 사용 설명서다.
```

## 한눈에 보기

| 항목 | 기록할 내용 |
| --- | --- |
| 목적 | 이 프롬프트를 왜 쓰는지 |
| 사용 상황 | 언제 쓰면 좋은지 |
| 프롬프트 | 실제로 입력할 문장 |
| 결과 | AI가 만든 결과가 어땠는지 |
| 개선점 | 다음에는 어떻게 바꿀지 |
| 태그 | 요약, 코딩, 리뷰, 글쓰기 같은 분류 |

## 1. 오늘 이걸 공부한 이유

좋은 프롬프트를 한 번 만들었는데 저장하지 않으면 다음에 또 비슷한 고민을 반복하게 된다.

```text
전에 괜찮게 나왔던 프롬프트가 뭐였지?
이 상황에서는 어떤 형식으로 요청했더라?
왜 그때 결과가 좋았지?
```

프롬프트를 기록하면 AI 활용 경험이 쌓인다. 그냥 사용한 시간이 아니라 재사용 가능한 자산이 된다.

## 2. 프롬프트를 저장하는 기준

모든 프롬프트를 저장할 필요는 없다. 아래 기준에 해당하면 저장할 만하다.

```text
다음에도 반복해서 쓸 가능성이 있다.
결과가 특히 좋았다.
처음에는 별로였지만 개선 과정이 유용했다.
내 공부나 업무 흐름에 자주 등장한다.
다른 프롬프트의 기본 템플릿으로 쓸 수 있다.
```

## 3. 프롬프트 기록 템플릿

프롬프트는 아래 형식으로 저장하면 좋다.

```md
# 프롬프트 이름

## 목적

이 프롬프트를 왜 사용하는지 적는다.

## 사용 상황

언제 쓰면 좋은지 적는다.

## 프롬프트

```text
실제 프롬프트를 적는다.
```

## 결과 리뷰

좋았던 점과 부족했던 점을 적는다.

## 개선 포인트

다음에 바꿔볼 부분을 적는다.

## 태그

- 요약
- 공부
- 개발
```

## 4. 실패한 프롬프트도 기록하기

실패한 프롬프트도 중요하다. 왜냐하면 실패 원인을 알면 다음 프롬프트가 좋아지기 때문이다.

```text
너무 애매했다.
출력 형식을 지정하지 않았다.
맥락이 부족했다.
AI에게 역할을 주지 않았다.
원하는 수준을 말하지 않았다.
```

실패 기록은 나중에 좋은 프롬프트를 만드는 재료가 된다.

## 5. 학습 기록과 연결하기

프롬프트 라이브러리는 공부 기록과 연결되어야 한다.

```text
오늘 무엇을 공부했는가?
어떤 프롬프트를 사용했는가?
결과가 좋았는가?
무엇을 개선했는가?
다음에 다시 쓸 수 있는가?
```

이렇게 남기면 AI 활용 공부가 단순한 사용 경험이 아니라 축적되는 학습이 된다.

## 6. 설명할 수 있는 문장

프롬프트 라이브러리에 대해서는 이렇게 설명할 수 있다.

> 프롬프트 라이브러리는 자주 쓰는 AI 요청을 목적과 사용 상황별로 정리한 개인 지식 저장소입니다. 좋은 프롬프트뿐 아니라 실패한 프롬프트와 개선 과정도 함께 기록하면, AI 활용 경험이 재사용 가능한 자산으로 쌓입니다.
