# 여섯 번째 학습: AI와 함께하는 개발 작업 흐름

> 목표: 개발 작업 전체 흐름에서 AI를 어디에 쓰면 좋은지 이해하고, 요구사항 이해부터 테스트와 리뷰까지 AI를 안전하게 활용하는 방법을 익힌다.

## 오늘의 결론

```text
AI는 개발 작업의 한 단계만 도와주는 도구가 아니다.
요구사항 이해, 작업 계획, 구현 방향 정리, 테스트 케이스 작성, 코드 리뷰까지 흐름 전체에서 활용할 수 있다.
다만 AI가 만든 계획과 코드는 반드시 개발자가 직접 검토하고 실행 결과로 확인해야 한다.
```

## 한눈에 보기

| 단계 | AI 활용 방법 |
| --- | --- |
| 요구사항 이해 | 요구사항을 요약하고 애매한 조건을 질문으로 뽑기 |
| 작업 계획 | 구현 순서, 영향 범위, 위험 요소 정리하기 |
| 구현 전 점검 | 필요한 파일, 함수, 테스트 범위 예상하기 |
| 구현 | 작은 단위의 코드 초안이나 예시 참고하기 |
| 테스트 | 정상, 예외, 경계값 테스트 케이스 만들기 |
| 리뷰 | 버그 가능성, 가독성, 중복, 누락된 테스트 확인하기 |

## 1. 오늘 이걸 공부한 이유

개발자가 AI를 쓸 때 흔한 실수는 바로 코드를 요구하는 것이다.

```text
이 기능 만들어줘.
이 코드 고쳐줘.
이 에러 해결해줘.
```

이렇게 물어보면 빠르게 답은 받을 수 있지만, 내가 문제를 제대로 이해하지 못한 상태에서 AI 답변을 따라가게 될 수 있다.

개발 작업에서는 코드보다 먼저 이해와 계획이 중요하다.

## 2. 요구사항 이해에 활용하기

작업을 시작하기 전에 AI에게 요구사항을 정리하게 할 수 있다.

```text
너는 백엔드 개발 작업을 도와주는 시니어 개발자야.
아래 요구사항을 읽고 바로 구현하지 말고 먼저 정리해줘.

결과는 아래 형식으로 작성해줘.

1. 작업 목표
2. 사용자가 기대하는 동작
3. 확인해야 할 애매한 조건
4. 영향을 받을 수 있는 기능
5. 구현 전에 물어봐야 할 질문

요구사항:
[여기에 요구사항 붙여넣기]
```

## 3. 작업 계획에 활용하기

요구사항을 이해한 뒤에는 구현 순서를 정한다.

```text
위 요구사항을 구현하기 위한 작업 계획을 세워줘.
바로 코드를 작성하지 말고, 작은 단계로 나눠줘.
각 단계마다 확인해야 할 점과 테스트할 내용을 적어줘.
```

좋은 작업 계획은 보통 이런 형태가 된다.

```text
1. 기존 코드 흐름 확인
2. 변경이 필요한 지점 찾기
3. 작은 단위로 수정
4. 정상 케이스 테스트
5. 예외 케이스 테스트
6. 영향 범위 확인
7. 코드 리뷰
```

## 4. 구현 중에는 작게 묻기

AI에게 큰 기능 전체를 맡기기보다 작은 단위로 묻는 것이 좋다.

```text
이 함수의 책임이 너무 많은지 봐줘.
이 조건문을 더 읽기 쉽게 바꿀 수 있는 방향만 제안해줘.
이 예외 처리가 빠진 케이스가 있는지 확인해줘.
```

작게 물으면 내가 판단하기 쉽고, AI가 틀려도 위험이 작다.

## 5. 테스트에 활용하기

AI는 테스트 케이스를 떠올리는 데 특히 좋다.

```text
아래 기능에 필요한 테스트 케이스를 제안해줘.
정상 케이스, 예외 케이스, 경계값 케이스로 나눠줘.
각 테스트가 왜 필요한지도 설명해줘.

기능:
[기능 설명]
```

## 6. 리뷰에 활용하기

구현한 뒤에는 AI를 리뷰어처럼 사용할 수 있다.

```text
아래 변경 내용을 코드 리뷰 관점에서 봐줘.
버그 가능성, 가독성, 중복, 성능, 테스트 누락을 기준으로 확인해줘.
위험도가 높은 문제부터 정리해줘.

변경 내용:
[코드 또는 설명]
```

## 7. 설명할 수 있는 문장

AI와 함께하는 개발 작업 흐름은 이렇게 설명할 수 있다.

> 개발에서 AI는 코드를 대신 쓰는 도구로만 쓰기보다 요구사항 이해, 작업 계획, 테스트 케이스 작성, 코드 리뷰에 활용할 때 더 안전합니다. 특히 바로 구현을 맡기기보다 애매한 조건과 위험 요소를 먼저 찾게 하면 개발자가 더 정확하게 판단할 수 있습니다.
