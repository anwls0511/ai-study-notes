# 두 번째 학습: 프롬프트 구조와 개선

> 목표: 좋은 프롬프트의 기본 구조를 익히고, 애매한 요청을 구체적인 요청으로 바꿀 수 있게 된다.

## 오늘의 결론

```text
좋은 프롬프트는 AI가 헷갈리지 않게 만든 지시문이다.
역할, 목표, 맥락, 제약 조건, 출력 형식을 넣으면 답변의 품질이 안정된다.
첫 답변이 부족하면 다시 질문하는 것이 아니라 구체적으로 개선 요청을 해야 한다.
```

## 한눈에 보기

| 요소 | 의미 | 예시 |
| --- | --- | --- |
| 역할 | AI가 맡을 입장 | 너는 친절한 학습 코치야 |
| 목표 | 내가 얻고 싶은 결과 | 이 개념을 내 말로 설명하고 싶어 |
| 맥락 | 현재 상황과 배경 | 나는 AI 활용을 처음 공부해 |
| 제약 조건 | 지켜야 할 기준 | 어려운 용어는 피하고 예시를 넣어줘 |
| 출력 형식 | 답변 모양 | 핵심 요약, 쉬운 설명, 예시 순서로 작성해줘 |

## 1. 기본 공식

프롬프트를 처음 만들 때는 아래 공식을 그대로 사용해도 좋다.

```text
너는 [역할]이야.
내 목표는 [목표]야.
현재 상황은 [맥락]이야.
다음 조건을 지켜줘: [제약 조건]
결과는 [출력 형식]으로 작성해줘.
```

## 2. 나쁜 프롬프트를 고쳐보기

나쁜 프롬프트는 보통 짧고 애매하다.

```text
보고서 써줘.
```

이 프롬프트는 AI가 다음 내용을 알 수 없다.

```text
무슨 보고서인가?
누가 읽는가?
분량은 어느 정도인가?
문체는 어떻게 해야 하는가?
무엇을 반드시 포함해야 하는가?
```

개선하면 이렇게 바꿀 수 있다.

```text
너는 실무 보고서 작성을 도와주는 비즈니스 글쓰기 코치야.
나는 AI 활용 공부 내용을 팀원에게 공유하는 1페이지 보고서를 작성하고 싶어.
읽는 사람은 AI를 잘 모르는 비개발자도 포함되어 있어.
어려운 용어는 쉽게 풀어쓰고, 실제 활용 예시를 포함해줘.
결과는 제목, 핵심 요약, 활용 사례, 다음 액션 순서로 작성해줘.
```

## 3. 다시 요청하는 방법

첫 답변이 부족할 때는 부족한 지점을 정확히 말해야 한다.

```text
설명이 아직 어려워.
중학생도 이해할 수 있을 정도로 더 쉽게 바꿔줘.
그리고 예시를 하나 더 추가해줘.
```

```text
내용은 좋은데 너무 길어.
핵심만 5줄로 줄이고, 마지막에 내가 바로 실행할 행동 3개를 적어줘.
```

```text
표현이 너무 딱딱해.
친근한 말투로 바꾸되, 내용의 정확성은 유지해줘.
```

## 4. 바로 써볼 프롬프트

```text
아래 프롬프트를 더 좋은 프롬프트로 개선해줘.
역할, 목표, 맥락, 제약 조건, 출력 형식이 들어가게 바꿔줘.
그리고 개선한 이유를 항목별로 설명해줘.

프롬프트:
[여기에 내 프롬프트 입력]
```

## 5. 설명할 수 있는 문장

프롬프트 구조에 대해서는 이렇게 설명할 수 있다.

> 좋은 프롬프트는 AI에게 역할과 목표, 상황, 조건, 답변 형식을 분명히 알려주는 지시문입니다. 프롬프트가 구체적일수록 AI는 내가 원하는 방향에 가까운 답변을 만들 수 있고, 첫 답변이 부족하면 부족한 지점을 짚어 다시 개선 요청해야 합니다.
